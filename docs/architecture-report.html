Ek nazar mein

Architecture

MERN, 3 hisse

React (browser) → Express API (Node.js) → MongoDB. Yahi SRS mein likha hai aur yahi abhi bana hai. Koi naya framework nahi chahiye; bas backend mein ek services layer add karni hai jahan hisaab kitaab (fuel ka andaza, budget, crisis) rahega.

Naye packages

Sirf 3 zaroori

leaflet aur react-leaflet map ke liye (FR-11, 12), recharts charts ke liye (FR-09, 10). Baqi sab maujooda packages aur Node ke built-in fetch se ho jayega.

Bahar ki service

OpenRouteService

Raasta, doori, waqt aur jagah dhoondhna (FR-05, 06, 11). Free, API key backend ki .env mein. Map ki tiles OpenStreetMap se. Google Maps ki zaroorat nahi (billing account maangta hai).

Ahem had: OpenRouteService alternative raaste sirf 100 km se chhote safar ke liye deta hai. Lambe safar (jaise Lahore se Islamabad) ke liye do request bhejein: fastest aur shortest, phir jis mein kam fuel lage use "Recommended" kahein. Tafseel Map services mein.

Teer ka matlab: kaun kis ko request bhejta hai. Browser kabhi seedha database ya OpenRouteService ko call nahi karta.

Frontend (browser)

  • Screens dikhana, forms, validation ka pehla check.
  • Token localStorage mein, har request ke saath bheja jata hai.
  • Map aur charts sirf data dikhate hain; hisaab backend karta hai.

Backend (server)

  • Routes: URL ko controller se jodna.
  • Controllers: request padhna, check karna, jawab dena.
  • Services (naya): hisaab aur bahar ki API. Ek hi hisaab kai jagah kaam aata hai.
  • Models: database ka shape aur aakhri checks.

Database aur shared

  • MongoDB Atlas: 6 collections (3 bane hue, 3 naye).
  • shared/ folder: roles, fuel types, limits aur validation dono taraf ek hi jagah se.

FR-06: andaza kaise banega

litre = raaste ke km ÷ gaari ki km/l
rupay = litre × aakhri fuel entry ka Rs/L
Recommended = jis raaste par sab se kam litre

Price user ki aakhri FuelRecord ke pricePerLitre se. Koi entry na ho to user se price poochein. UI mein "andaza" likhein, kyunke traffic aur chadhaai shamil nahi.

FR-13: notification kab banegi

  • Fuel entry save hui → budget 80% ya 100% cross hua → notification.
  • Trip save hua aur chuna hua raasta recommended se 15%+ zyada fuel wala hai → "inefficient trip".
  • Crisis mode on hua → har naye mashware par notification.
  • Har notification ki ek key (jaise budget-2026-10-100) unique hai, is liye ek baat do dafa nahi aati.

"Optimized raasta" kaise nikalein

  • 100 km se kam: ek request, alternative_routes ke saath (2-3 raaste).
  • 100 km se zyada: do request, preference: "fastest" aur "shortest".
  • Har raaste par FR-06 wala formula; sab se kam litre wala "Recommended".
  • Jawab geojson format mein mangwayein, taake Leaflet seedha line bana de.

Quota bachana

  • API key sirf backend .env mein (ORS_API_KEY), kabhi frontend mein nahi.
  • Jagah ki search tab bhejein jab user 3+ letter likh kar ruke (300 ms).
  • Ek hi jagah ka jawab server ki memory mein yaad rakhein (simple Map cache).
  • Trip save karte waqt raasta bhi save karein, taake dekhne par dobara call na ho.
  • ORS band ho to trip phir bhi save ho, aur saaf message aaye.

Trip planning (FR-05, 06, 11, 12): browser kabhi OpenRouteService ko seedha call nahi karta.

Budget alert (FR-08 + FR-13)

  1. User fuel entry save karta hai (POST /api/fuel-records).
  2. budgetService us mahine (Pakistan time) ka kharcha jodta hai aur budget se milata hai.
  3. 80% ya 100% cross hua to notificationService notification banata hai, key budget-2026-10-80 ya -100; key unique hai, is liye dobara nahi banti.
  4. Frontend ki bell har minute aur tab par wapas aane par ginti check karti hai; dashboard ka budget card laal ho jata hai.
  5. Entry delete ho aur kharcha budget se kam ho jaye to card wapas theek dikhta hai (status har dafa naye sire se nikalta hai).
Poore system ke rules

Har nayi feature mein yeh rules

Security

  • Har naya route protect ke peeche; ownership check isOwnerOrAdmin se.
  • Secrets (JWT_SECRET, ORS_API_KEY) sirf backend .env mein.
  • Client se aaye fields whitelist se (pick jaisa), jaise pricePerLitre aur user kabhi client se nahi.
  • Admin sirf seeder ya doosre Admin se banta hai.

Data aur code

  • Validation ek jagah: shared/validation.js (form aur server dono).
  • Mahina aur "aaj" Pakistan time (Asia/Karachi) se.
  • Errors hamesha JSON; user ki ghalti par 400, kabhi 401 nahi (401 logout karta hai).
  • Har cascade delete: user → gaariyan → fuel records, trips, budgets, notifications.
