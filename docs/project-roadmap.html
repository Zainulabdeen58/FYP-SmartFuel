FR-01

Account: register, login, profile, logout

Mukammal Phase 0
The system shall allow users (individual, organizational, and admin) to register an account, log in securely, update their personal profile, and log out.

Matlab: User account bana sake, password ke saath mehfooz login kare, apni profile badal sake aur logout kar sake. Teen qisam ke account hon.

Abhi bana hai: Teeno account types ke saath register, login (JWT token aur bcrypt password), profile update aur logout. Server khud email, phone aur password check karta hai. Login expire hone par app khud logout kar deti hai.

Files: backend/controllers/authController.js, userController.js, backend/utils/validation.js, frontend/src/api.js, AuthPage.jsx, Profile.jsx

Edge cases
  • Same email dobara, ya capital letters ke saath (Ali@x.com aur ali@x.com). Handled
  • Organizational account ka option nahi tha. Ab register par "Organization" option aur organization name hai. Fixed
  • 6 se chhota password seedha API se bheja jaye to server ab reject karta hai. Fixed
  • Koi bhi register karte waqt Admin chun kar poore system ka control le sakta hai. Decide
  • Token 1 din baad expire ho to app ab khud logout karke login page par le jati hai. Fixed
  • Ek computer par user A ke baad user B login kare to Profile ab B ka data dikhata hai, aur profile badalne par naya naam fori har jagah dikhta hai. Fixed
  • Naya password set karne ke liye ab current password zaroori hai. Fixed
  • Delete ho chuke user ka token use ho to "User no longer exists". Handled
FR-02

Vehicle add karna

Mukammal Phase 0 (fixes)
The system shall allow users to add new vehicles with attributes including fuel efficiency and tank capacity.

Matlab: Gaari add karna: naam, registration number, company, model year, fuel type, fuel efficiency (km/l) aur tank capacity (litre).

Abhi bana hai: Saari fields ke saath add form aur API.

Files: backend/models/Vehicle.js, vehicleController.js, frontend/src/components/VehicleForm.jsx

Edge cases
  • Fuel efficiency aur tank capacity ab 0 se zyada lazmi hain, form aur server dono par. Fixed
  • Same registration number dobara add karne par ab "already exists" error aata hai. Fixed
  • Model year ki had (1980 se agle saal tak) ab server bhi check karta hai. Fixed
  • Electric gaari ke liye km/l aur litre tank ka matlab nahi banta (kWh hona chahiye). Decide
  • Negative values server par ruk jaati hain. Handled
  • Registration number chhote harfon ya space ke saath likha jaye to khud bade harf aur trim. Handled
FR-03

Vehicle dekhna, edit, delete

Mukammal Phase 0 (fixes)
The system shall allow users to view, update, or delete vehicle information at any time.

Matlab: User apni gaariyon ki list dekhe, kisi bhi waqt badle ya delete kare.

Abhi bana hai: List, edit aur delete. Individual sirf apni gaariyan dekhta hai, Admin sab.

Files: backend/controllers/vehicleController.js, frontend/src/components/Vehicles.jsx, Admin.jsx

Edge cases
  • Doosre user ki gaari ka ID kholne par "Not authorized". Handled
  • Ghalat ID (jaise "abc") par ab saaf JSON error "Invalid id" aata hai. Fixed
  • Edit mein ghalat value (jaise fuel type "Gas") par ab 400 aur saaf message. Fixed
  • Jis gaari ke fuel records hon, use delete karne par records bhi saath delete hote hain (confirm box mein likha hai). Fixed
  • Page load par ab "Loading vehicles..." dikhta hai, "No vehicles yet" nahi chamakta. Fixed
FR-04

Fuel purchase records

Mukammal Phase 1
The system shall allow users to create, read, update, and delete fuel purchase records linked to vehicles, including date, quantity, and cost.

Matlab: Jab bhi petrol ya diesel dalwayein, entry karein: kis gaari mein, kab, kitne litre, kitne rupay. Entries dekh, badal aur delete kar saken.

Fields (proposal): gaari, date, quantity (litre), total cost (Rs), price per litre (khud calculate), odometer reading (km, optional), petrol pump (optional).

Odometer isliye: khareeda hua fuel aur jala hua fuel ek cheez nahi. Asal km/l nikalne ke liye do refills ke beech ke km chahiye.

Faisle (10 Oct 2026): gaari delete ho to us ke records bhi delete. Electric gaari par fuel record nahi banta. Rs 100 se kam ya Rs 1,000 se zyada per litre reject. Date Pakistan time ke din ke hisaab se save hoti hai.

Edge cases
  • Quantity tank se zyada (60 L tank mein 80 L) ho to reject. Fixed
  • Quantity ya cost 0 ya negative ho to reject. Fixed
  • Aane wali (future) date ho to reject. Fixed
  • Price per litre Rs 100 se kam ya Rs 1,000 se zyada ho (typing ki ghalti) to reject. Fixed
  • Gaari kisi aur user ki ho to "Not authorized". Fixed
  • Electric gaari par fuel record block (form aur server dono). Fixed
  • 31 tareekh raat 11:30 ki entry agle mahine mein na jaye: date sirf din ke taur par (Pakistan time) save hoti hai. Fixed
  • Purani entry edit ya delete ho to us mahine ka budget aur charts dobara hisaab hon. Phase 2 aur 3
FR-05

Trips banana

Shuru nahi Phase 4
The system shall allow users to create trips by specifying a starting point and destination.

Matlab: Safar plan karna: kahan se kahan, kis gaari se, kis din.

Fields (proposal): gaari, start (naam aur location), destination, date, maqsad, priority (zaroori ya ghair-zaroori), status (planned ya completed).

Priority SRS mein nahi likhi, lekin crisis mode (FR-07) ko "ghair-zaroori safar" pehchanne ke liye yahi chahiye.

Edge cases
  • Jagah ka naam na mile, ya kai jagah milen (jaise "Saddar" Karachi aur Rawalpindi dono mein). List dikha kar user se chunwayein.
  • Start aur destination ek hi jagah ho to reject.
  • Sadak ka koi raasta hi na ho to saaf message.
  • Safar tank ki range se lamba ho (distance zyada ho efficiency × tank se) to "raste mein fuel bharna hoga".
  • Map ya route API band ho ya limit khatam ho jaye to trip phir bhi save ho, andaza baad mein.
  • Gaari select na ki ho to fuel ka andaza nahi ho sakta, isliye gaari zaroori.
FR-06

Fuel ka andaza aur optimized route

Shuru nahi Phase 4
The system shall calculate the estimated fuel required and suggest optimized routes to minimize fuel consumption.

Matlab: Safar ke liye kitna fuel lagega aur kitne paise, yeh batana. Kai raaston mein se kam fuel wala raasta suggest karna.

fuel (L) = distance (km) ÷ efficiency (km/l)
kharcha (Rs) = fuel (L) × price per litre
Misaal: 120 km ÷ 12 km/l = 10 L · 10 L × Rs 265 = Rs 2,650

Price user ki aakhri fuel entry se. Misaal ka Rs 265 sirf samjhane ke liye hai.

Edge cases
  • Efficiency 0 ya khaali ho to 0 se divide. Isliye FR-02 mein 0 se zyada lazmi.
  • User ki koi fuel entry nahi to price kahan se aaye: default price ya user se poochein.
  • Sirf ek raasta mile to wahi dikhayein aur likhein "alternative nahi mila".
  • Chhota raasta zyada waqt le (traffic) to fuel aur time dono dikhayein, user chune.
  • Yeh andaza hai. Chadhaai, traffic aur AC ka asar shamil nahi, UI mein bhi "andaza" likhein.
FR-07

Crisis mode

Shuru nahi Phase 5
The system shall provide a "crisis mode" that recommends strategies such as combining trips or avoiding non-essential travel to conserve fuel.

Matlab: Fuel ki kami ke dino ka mode jo mashware de: safar mila lo, ghair-zaroori safar chhor do.

Rules (proposal):

  • Ek hi din ke trips jinki manzil qareeb ho (jaise 5 km ke andar): "inhein ek safar mein milayein".
  • Ghair-zaroori priority wala trip: "aage karein ya cancel karein".
  • Kitne litre aur rupay bachenge, yeh bhi dikhayein.
Edge cases
  • Mode kaun on kare: har user khud, ya Admin poore system ke liye? Supervisor se poochein.
  • Koi trip planned na ho to sirf aam tips dikhayein.
  • Purane trips jinki priority nahi, unhein "unknown" maan kar user se poochein.
  • Sirf ek trip ho to "combine" ka mashwara na dein.
  • Mode band karne par mashware hat jayen, user ka data delete na ho.
FR-08

Monthly budget aur alerts

Shuru nahi Phase 2
The system shall allow users to set monthly fuel budgets, track fuel expenses automatically, and display alerts when budgets are exceeded through a user dashboard.

Matlab: Har mahine ka fuel budget set karna (jaise Rs 30,000). Fuel entries ka kharcha khud jud kar dikhe. Budget cross ho to dashboard par alert.

Edge cases
  • Budget set hi nahi kiya to alert nahi, dashboard par "budget set karein" ka button.
  • Budget 0 ya negative ho to reject.
  • Mahine ke beech budget badla to naye budget se dobara hisaab.
  • Alert baar baar na aaye: 80% par ek warning, 100% par ek alert, har mahine ek dafa.
  • Entry delete karne se kharcha budget ke andar aa jaye to alert hat jaye.
  • Mahina Pakistan time ke hisaab se (FR-04 wala timezone case).
  • Organizational: poori fleet ka ek budget, chahein to har gaari ka alag.
FR-09

Charts aur graphs

Shuru nahi Phase 3
The system shall provide visual charts and graphs showing total fuel consumption, costs over time, and per-vehicle statistics.

Matlab: Graphs: har mahine kitne litre aur kitne rupay, aur har gaari ka muqabla (litre, kharcha, average km/l).

Edge cases
  • Koi data nahi to khaali chart ki jagah "pehli fuel entry add karein".
  • Sirf ek entry ho to line chart ki jagah seedha number ya bar.
  • Delete ho chuki gaari ka purana data: "Deleted vehicle" naam se dikhayein ya chhupa dein.
  • Electric (kWh) aur petrol (litre) ko ek hi chart mein na milayein.
  • Odometer na ho to chart par "khareeda gaya fuel" likhein, "consumption" nahi.
FR-10

Dashboard filters

Shuru nahi Phase 3
The system shall allow users to filter and interact with dashboards to analyze fuel usage patterns.

Matlab: Dashboard par filter: date range, gaari, fuel type. Chart par mouse le jane se values dikhen.

Edge cases
  • Start date end date ke baad ho to error dikhayein.
  • Filter ka koi result na ho to "is filter mein data nahi".
  • Bohat lamba range (5 saal) ho to mahine ki jagah saal ke hisaab se dikhayein.
  • Page refresh par chuna hua filter yaad rahe.
FR-11

Map par route dikhana

Shuru nahi Phase 4
The system shall display planned and optimized routes on a map, including distance, estimated fuel consumption, and travel time.

Matlab: Map par raaste ki line, saath mein distance (km), andazan fuel (L) aur waqt (minute).

Edge cases
  • Internet slow ho aur map load na ho to bhi route ki details text mein dikhen.
  • Kai raaste hon to recommended raasta alag rang mein, baqi halke.
  • OpenStreetMap aur route provider ka naam (attribution) map par dikhana zaroori hai.
  • API key frontend code mein na ho. Call backend ke zariye karein.
  • Mobile par map ki height aur controls theek hon.
FR-12

Map zoom, pan, interact

Shuru nahi Phase 4
The system shall allow users to zoom, pan, and interact with the map for better trip planning.

Matlab: Map ko zoom in/out karna, khiskana (pan), aur raaste ya marker par click karke details dekhna. Leaflet yeh sab khud deta hai.

Edge cases
  • Mobile par do ungliyon se zoom, aur page scroll aur map pan aapas mein na takrayein.
  • Bohat zyada zoom out (poori duniya) na ho, Pakistan ke aas paas had lagayein.
  • Keyboard se bhi zoom (+ aur −) chale.
FR-13

Notifications

Shuru nahi Phase 6
The system shall notify users of critical events, including budget limits exceeded, inefficient trips, or recommended actions during crisis mode.

Matlab: Zaroori baaton par notification: budget cross, inefficient trip, crisis mode ke mashware.

Proposal: App ke andar bell icon aur list (read/unread). Email baad mein, agar supervisor kahe.

Edge cases
  • "Inefficient trip" ki tareef SRS mein nahi. Proposal: chuna gaya raasta recommended se 15% ya zyada fuel le.
  • Ek hi baat ki notification baar baar na bane.
  • Notification jis cheez ki taraf le jaye woh delete ho chuki ho to "yeh item ab maujood nahi".
  • Bohat purani notifications 60 din baad saaf ho jayen.
  • Har user ko sirf apni notifications dikhen.

Supervisor sawalat

SRS mein jo saaf nahi likha

Yeh baatein code shuru karne se pehle supervisor se poochein. Inke jawab se phases ka kaam badal sakta hai.

  1. Organizational account ka matlab kya hai?Sirf ek login se poori fleet, ya organization ke andar members aur drivers ke alag logins?
  2. Admin account kaun bana sakta hai?Register page se koi bhi, ya sirf pehle se maujood Admin?
  3. Crisis mode kaun on karta hai?Har user khud, ya Admin poore system ke liye?
  4. "Inefficient trip" kis ko kahenge?Hamari proposal: chuna gaya raasta recommended raaste se 15% ya zyada fuel le.
  5. Notifications sirf app ke andar kaafi hain?Ya email bhi chahiye?

  7. Fuel ki qeemat kahan se aaye?User ki aakhri entry se, ya user khud set kare?
